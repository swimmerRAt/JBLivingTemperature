## 화면에서 확인

앱 하단 **30분 생활권과 인프라 관계 분석**에서 **평일 분석 출발 시각**을 선택합니다. 30분 안에 도달하는 병의원·약국 합계와 각각의 시설 수를 표시합니다. 센터 위치 미확인 또는 보행망 연결이 불가능한 지역은 계산 불가 사유를 표시합니다. 실제 일자리 위치가 없으므로 일자리 접근성은 계산하지 않습니다.

## 계산 방식과 해석

- KTDB 2025년 3월 대표 평일 시각표, HIRA 2025년 3월 의료시설, OSM 2026년 10월 15일 지도망을 결합한 시나리오 추정입니다. 자료 시점이 다르므로 2025년 당시의 완전한 재현이나 2026년 현재의 실시간 결과가 아닙니다.
- KTDB 특수 코드 `route_type=0`을 시내·농어촌·마을버스로 해석합니다. 시외버스·철도·항공·해운은 포함하지 않습니다.
- KTDB 설명서에 따르면 달력의 전 요일 운행 및 2017~2030 유효기간은 분석 편의를 위한 인공 코딩입니다. 이를 실제 주말·현재 운행으로 해석하지 않습니다.
- 도보 단독 경로와 도보→버스→도보 경로를 함께 탐색합니다. 버스의 정류장별 도착·출발 시각, 승하차 제한, 차량 내 계속 탑승, 보행 환승을 반영합니다. 매 승차 30초의 여유를 두고 탈 수 있는 다음 버스를 찾으므로 승차·환승 대기가 포함됩니다. 배차간격 절반을 대기로 넣지 않습니다.
- 시간표에서 1km 이상의 정류장 간 직선거리를 시속 130km 넘게 이동해야 하거나 100m 넘는 거리를 0초에 이동하는 운행편은 통째로 제외합니다. 이는 법정 제한속도가 아닌 보수적인 자료 품질 기준입니다. 시간을 임의로 늘려 대체하지 않으며 `excluded_timetable_jumps.csv`에 제외 근거를 보존합니다.
- 보행시간은 OSM 길의 길이와 80m/분의 속도로 추정합니다. 사유지·명시적 보행 금지·고속도로 등은 제외하며 보행 일방통행을 반영합니다. 차량 일방통행을 보행 일방통행으로 오해하지 않습니다.
- 출발점·정류장·시설 좌표는 가장 가까운 보행 도로 구간에 투영합니다. 도로까지 100m 이하의 연결 구간은 직선 거리 추정이며 이동시간에 포함합니다. 강·담장·건물 출입구를 정밀 검증한 실제 보행 경로는 아닙니다. 100m를 넘으면 임의 연결하지 않습니다.
- 경로의 도로·정류장은 전북 경계의 5km 완충 영역을 둘러싸는 사각 범위에서 보존합니다. 선택된 운행편의 전체 정류장 순서와 시각은 유지하여 경계 밖으로 나갔다 들어오는 버스에서 계속 탑승할 수 있게 합니다. 범위 밖의 보행 환승은 제공하지 않습니다.
- 출발점은 읍면동 행정복지센터·주민센터·읍면사무소입니다. OSM 명칭과 현행 경계를 대조하며, 금암동 통합청사는 전주시 공식 안내로 선택했습니다. 센터 위치 미확인 지역은 다른 좌표로 대체하지 않습니다. 센터 기준 결과이며 주민 전체의 접근성을 뜻하지 않습니다.
- 기관 영업시간·진료과목·실시간 결행·혼잡·교통약자 통행조건은 반영하지 않습니다. 시설 누락과 OSM 연결 오류 때문에 과소 또는 과대 추정할 수 있습니다.
- 기존 상대 생활 점수의 교통 항목은 정류장 밀도·노선 수를 유지합니다. 일부 지역만 계산된 시간표 접근성을 전 지역 점수에 조용히 대체하지 않습니다.

## 다시 계산

프로젝트 가상환경에서 `requirements.txt`를 설치한 뒤 다음을 실행합니다.

```bash
python scripts/build_admin_center_origins.py
python scripts/download_living_facilities.py      # 생활시설 공공데이터 수집·경로당 지오코딩 (처음 약 45분, 이후 캐시 재사용)
python scripts/prepare_accessibility_sources.py
python scripts/build_scheduled_accessibility.py
```

`download_living_facilities.py`는 `data/raw/facilities/`에 원본이 있으면 다시 받지 않습니다. 새 기준으로 받으려면 `--force`를 붙입니다. 생활시설 표가 없으면 기존처럼 병의원·약국만 계산합니다.

첫 명령은 OSM에서 센터 위치를 추출하고, 두 번째 명령은 전국 원본을 읽어 전북과 주변 노선, 실제 보행 도로망, 출발점·정류장·시설 연결 정보를 준비합니다. 세 번째는 오전 8시·정오·오후 6시 출발 결과를 생성합니다. `--departures 09:00:00 15:00:00`처럼 출발 시각을 바꿀 수 있습니다. 특정 지역 점검은 `--region 지역코드`로 실행하며 전체 결과를 덮어쓰지 않습니다. 보행속도·최대 연결 거리는 준비 명령의 `--walking-speed`, `--max-connector`로 조정합니다. 가정을 바꾼 결과는 별도 시나리오로 해석해야 합니다.

과거의 수동 CSV 기반 엔진인 `scripts/build_accessibility.py`도 남아 있지만, 현재 다운로드 자료를 이용한 결과는 위 두 명령으로 생성합니다.

## 인프라 관계 분석과 가중치

```bash
python scripts/analyze_infrastructure.py
```

SQLite에서 읍면동·연도 패널을 구성하고 동일 조사기준의 2020년 이후 사업체·시군 빈집 자료로 전년도 인프라와 청년 순이동 추정의 관계를 분석합니다. 청년 순이동은 5세 구간 내 균등 연령분포·사망 미반영 가정의 1년 코호트 잔차입니다. 실제 전입·전출 관측값이 아닙니다. 읍면동·연도 고정효과와 시군 군집 표준오차를 사용합니다. 현재 242개 읍면동, 2021~2025년 1,202건에서 유의한 양의 계수가 없어 가중치는 유지합니다. 이는 관계가 없다는 증거나 인과효과를 의미하지 않습니다.

별도로 준비한 패널은 `--panel 경로.csv`로 분석합니다. 필수 열은 `region_code,year,youth_net_migration_rate`이며 이동률 단위는 천 명당입니다. 설명변수는 `transport_access,medical_access,establishments,city_vacant_house_ratio` 중 확보한 항목입니다. 이번의 단일 시점 접근성을 모든 과거 연도에 복제해 회귀하지 않습니다. 유의한 양의 계수가 있으면 사이드바에서 해당 항목끼리의 가중치 재배분을 선택할 수 있습니다. 자동 적용하지 않습니다.

## 의료 관측 변화와 점수 근거

화면 **의료시설 변화와 평가 근거**에서 병의원·약국의 시점별 기관 수, 최소 12개월 앞선 자료 대비 증감, 위치 배정률을 확인합니다. 종류·시점 전체의 위치 자료가 없으면 0개로 바꾸지 않으며 기준 기관 수가 0개이면 증감률을 계산하지 않습니다. 이는 실제 개·폐업 판정이나 미래 감소 예측이 아닙니다.

현재 가중치에서 항목 하나씩 ±20% 조정한 공동순위·등급 범위를 함께 표시합니다. 통계적 신뢰구간이 아닙니다. 항목별 자료 범위·결측·중립 점수·대체 지표도 보여줍니다.

## 교통 이력 수집

이번 KTDB 자료는 한 평일의 시간표이므로 교통 감소 예측을 위한 연도별 이력을 대신하지 못합니다. `.env`에 승인된 `DATA_GO_KR_API_KEY`를 설정하면 다음 수집 기능을 사용할 수 있습니다.

```bash
python scripts/collect_transport_history.py
python scripts/collect_transport_history.py --interval-hours 24
```

첫 명령은 1회, 두 번째는 프로세스가 실행 중일 때 매일 반복합니다. 자동 시작 작업은 등록하지 않았습니다. 정류장·노선·경유 정류장·평일/주말 배차 상세를 `data/raw/tago/history/<UTC 시각>/`에 보존하며 완료 이력에 SHA-256 manifest를 기록합니다. API 키 설정과 실제 수집 가동은 별도입니다.
